\section{Introduction}

This project studies the key design choices in SimCLR for visual representation learning. Instead of training a new supervised classifier from labels only, SimCLR first learns an encoder from unlabeled images. Two random views are generated from each image, and the model is trained to make the two views of the same image close while pushing views from different images apart. After pretraining, the encoder is frozen and a simple linear classifier is trained on top of its features. If the linear classifier performs well, the encoder has learned useful
visual representations.

According to our project plan, the main goal is not to build a more complex model, but to understand which SimCLR components matter. The planned components are data augmentation, projection head, batch size, and low-label evaluation.

\section{Method}

\subsection{Baseline SimCLR}

Our baseline uses CIFAR-10 and a ResNet-18 backbone as encoder. During contrastive pretraining, each input image is transformed twice to produce two augmented views. The implementation uses random resized crop, horizontal flip, color jitter, random grayscale, and Gaussian blur. For a batch of $B$ original images, there are $2B$ views. For each anchor view, its positive example is the other view from the same original image, while the other $2B-2$ views are negatives.

The contrastive loss follows the NT-Xent form used by SimCLR:
\[
\ell_{i,j} =
-\log
\frac{\exp(\operatorname{sim}(z_i,z_j)/\tau)}
{\sum_{k=1}^{2B} \mathbf{1}_{k \ne i}
\exp(\operatorname{sim}(z_i,z_k)/\tau)} ,
\]
where $z$ is the normalized output used by the contrastive loss, $\operatorname{sim}$ is cosine similarity, and $\tau$ is the temperature. In our code the temperature is set to 0.07. The model is optimized with Adam and weight decay during pretraining.

\subsection{Projection Head}

The encoder output of ResNet-18 is a 512-dimensional feature vector. With the projection head enabled, this vector is passed through a two-layer MLP:
\[
512 \rightarrow 512 \rightarrow 128.
\]
The contrastive loss is applied to the projected vector. During linear
evaluation, however, the projection head is removed and the frozen
512-dimensional encoder feature is used. Without the projection head, the
contrastive loss is applied directly to the 512-dimensional encoder output. This comparison tests whether the extra nonlinear head helps the encoder learn better features for later classification.

\subsection{Linear Evaluation}

We use linear evaluation as the main metric. The pretrained encoder is frozen, features are extracted for CIFAR-10 train and test images, and a single linear layer is trained for 100 epochs. The classifier uses Adam with learning rate 0.001 and no weight decay. Accuracy on the CIFAR-10 test set is reported. This protocol is useful because it measures representation quality without allowing the encoder to change during evaluation.

The model with the projection head reaches 63.59\% best test accuracy, while the model without the projection head reaches 62.16\%. This is an improvement of 1.43 percentage points. The final accuracy also improves from 61.40\% to 62.84\%, which is a 1.44 percentage point gain. The result supports the SimCLR idea that the projection head can absorb transformations needed by the contrastive objective, while the encoder output keeps more useful information for downstream classification.

The improvement is not extremely large, but it is consistent across best and final accuracy. Also, the model with the projection head reaches its best result later in linear evaluation. This suggests that its frozen features may contain slightly richer information that the linear classifier can use after more training.

\subsection{Batch Size Ablation}

Batch size changes the number of negatives in the contrastive loss. With two views per image, the number of negatives for each anchor is $2B-2$. We compare batch sizes 128, 256, 512, and 1024. The projection head is enabled for this ablation, and the same linear evaluation protocol is used for all four runs.

The best result is obtained at batch size 256, with 510 negatives per anchor and 63.47\% best test accuracy. Batch size 128 is slightly lower at 62.54\%, while batch sizes 512 and 1024 drop to 60.89\% and 57.56\%, respectively. Therefore, our result does not show the monotonic improvement with batch size that might be expected from the larger number of negative samples.

This differs from the main conclusion in the original SimCLR paper, which reports that contrastive learning benefits from larger batch sizes. The difference is plausible because our experiments' setting is much smaller and less tuned. The original SimCLR batch-size experiments mainly use ImageNet, a ResNet-50 backbone, LARS optimization, and a learning rate scaled with batch size. Therefore, they are not directly comparable to our lightweight setting. In contrast, our runs use CIFAR-10, ResNet-18, Adam with the same initial learning rate of 0.0003, and 100 epochs for every batch size. Under this setting, increasing the batch size changes more than the number of negatives, but also reduces the number of optimizer updates per epoch and changes how the learning process behaves.

For CIFAR-10, the dataset is also small and contains only ten classes. When the batch size becomes very large, many negative samples may actually look similar or belong to the same class as the anchor image. The contrastive loss then tries to separate samples that should actually stay close in representation space. This can make the self-supervised task more difficult without improving the final class representations. For example, the batch size 1024 experiment uses 2046 negative samples for each anchor, but it achieves the worst linear evaluation accuracy. This suggests that simply increasing the number of negatives does not always improve performance on CIFAR-10.

Another likely factor is hyperparameter mismatch. Large batch contrastive learning usually needs batch-size aware learning rate scaling and sometimes longer training. In our experiment, batch size 1024 has four times fewer parameter updates per epoch than batch size 256, but it uses the same number of epochs and the same initial learning rate. Therefore, the larger batch models may be trained with a poorly matched schedule relative to the 256 baseline. Overall, batch size 256 gives the best balance in our experiments. It provides enough negative samples to make contrastive learning effective, while avoiding the optimization problems and false-negative issues that can happen with very large batch sizes.

\section{Discussion}

The data augmentation xxxxxx.

The projection head ablation gives a clear result: using the projection head improves the final representation. It agrees with the motivation of SimCLR. The contrastive objective may require invariances that are useful for matching augmented views, but not all of these changes should be forced directly onto the encoder feature used by the downstream task. The projection head gives the model an extra space for optimizing the pretext task.

The batch size ablation gives a more mixed result than the original SimCLR trend. Batch size 256 is best, while 512 and 1024 are worse. This does not mean negative samples are unimportant. Rather, it shows that batch size is tied to optimization details and dataset scale. If batch size changes, the number of updates, learning rate behavior, false-negative frequency, memory pressure, and training stability can also change. Therefore, batch size should not be interpreted as only a negative sample count variable.

\section{Shortcomings}

There are several limitations in the current experiments. First, each setting is evaluated with a single seed, so the result may include random variation. Second, the batch size experiment does not retune the learning rate, temperature, optimizer, or schedule for each batch size. This makes the comparison practical but not fully isolated. Third, the experiments use CIFAR-10 and ResNet-18 only, so the conclusions may not transfer directly to larger datasets or architectures. Finally, we compare checkpoints trained for the same number of epochs rather than the same number of optimization steps, which disadvantages larger batches.

\section{Future Work}

Future work should run each setting with multiple seeds and report mean and standard deviation. The batch size ablation should also test learning-rate scaling, longer pretraining, LARS or SGD with momentum, temperature tuning, and schedules that are matched by number of optimization steps rather than only by epochs. After the low-label experiments are completed, we can compare SimCLR pretraining against direct supervised training under 1\%, 10\%, and 100\% label fractions. It would also be useful to add k-nearest-neighbor evaluation and feature-space visualization as supporting evidence.

\section{Conclusion}

This project studies SimCLR through controlled ablation experiments. For the completed parts, the projection head improves CIFAR-10 linear evaluation accuracy from 62.16\% to 63.59\%, showing that the nonlinear head is useful for learning transferable encoder features. The batch size ablation shows that batch size 256 performs best among 128, 256, 512, and 1024. The result suggests that more negatives are helpful only when optimization remains stable and the hyperparameters are matched to the batch size. Overall, SimCLR performance depends on both representation design and training details, so ablation studies are necessary for understanding why the method works.
